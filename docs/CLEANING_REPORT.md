# Notebook cleaning and reproducibility report

## Scope

The archive contained 30 executed main-analysis notebooks. They were reviewed as a
single dependency chain rather than as isolated files. The cleaned package contains
those 30 stages plus the separately recovered CellRank notebook, for 31 main-analysis
notebooks in total. The 12 finalized dataset-preprocessing notebooks are included under
`code/00_preprocessing/`.

## Cross-pipeline corrections

- Removed the machine-specific `/mnt/DATA/GBM_scRNA_project` root from every main
  notebook.
- Added repository-root discovery and the `GLIOMA_PROJECT_ROOT` override.
- Aligned the main integration inputs with the finalized preprocessing outputs under
  `data/processed/DS1_GSE103224` through `data/processed/DS4_GSE278450`.
- Standardized historical internal labels `DS5_GSE182109` and `DS13_GSE278450` to
  `DS3_GSE182109` and `DS4_GSE278450`.
- Moved generated integrated AnnData paths to `data/processed/integrated/` and CNV
  intermediates to `data/interim/`.
- Cleared stored cell outputs and execution counters so repository notebooks are small,
  reviewable, and do not present stale output as a fresh run.
- Added an execution-order table and original-to-clean filename mapping.

## Targeted corrections

### Merge and harmonization

The first notebook now reads the exact four post-QC files generated by the finalized
preprocessing workflows. It validates the reported integrated dimensions of 351,427
cells by 15,176 genes and uses a backed saved-file check instead of loading the full
object into memory a second time.

### scVI

The original notebook defined two different training configurations and hard-coded a
GPU accelerator in the actual training call. The cleaned version uses one configuration:
800 maximum epochs, early-stopping patience 50, minimum delta 0.001, validation every
five epochs, batch size 512, and automatic CPU/GPU selection. Model architecture and
reported integration parameters are unchanged.

### Online enrichment

The archived online-validation notebook relied on hidden kernel state: `RUN_ENRICHR`
and `enrichr_df` were referenced but not defined in the notebook. Enrichr was also
removed from the submitted manuscript. The notebook was replaced by a self-contained
g:Profiler-only workflow with retry handling and per-list error logging.

### LIANA and Squidpy

The preparation and validation stages now require the final malignant-state AnnData
object explicitly rather than silently selecting an earlier intermediate file when the
final object is absent.

### CellRank

The recovered memory-safe CellRank notebook is included as stage 31. It uses the final
integrated path, a stratified 20,000-cell subset, and includes direct code for the
Supplementary Fig. S9 maximum-membership and maximum-fate-probability panels.

## Validation performed

- All 43 included notebooks pass `nbformat` validation.
- All main-analysis Python code cells compile without syntax errors.
- No main notebook retains the machine-specific project path.
- No main notebook contains Enrichr execution or output references.
- All stored execution outputs were removed from the 31 main-analysis notebooks.

## Runtime limitation

End-to-end execution was not possible in the review environment because the original
GEO-derived count matrices, large AnnData objects, GENCODE reference, trained scVI
model, and CopyKAT R runtime are not present. Runtime assertions in the notebooks are
therefore intentionally retained: they will stop at the first mismatch in file content,
metadata, package behavior, or expected dimensions rather than silently producing a
different analysis.
