# Reproducing the patient-level sensitivity analyses

## Scope and saved results

The four public datasets contribute 83 samples from 57 source-backed patients: 39 GBM, 2 LGG, 11 ndGBM and 5 rGBM. DS3 contributes 18 distinct patients. Regional fragments are repeated observations within a patient. Cohort-prefixed DS3 identifiers such as `ndGBM-01` and `rGBM-01` refer to distinct patients; they are not a longitudinal pair.

The checked archive under [`supplementary/patient_level_sensitivity`](../supplementary/patient_level_sensitivity/) contains 39 saved output files from notebooks 02–04. It includes all gene-level patient DE results, rather than only top-gene summaries. It is the same ZIP supplied as manuscript Additional file 3. Use the provided manifests to check bytes and provenance. Integrity verification does not establish independent statistical replication.

## Verification without analysis

From the repository root:

```bash
python scripts/verify_patient_sensitivity_release.py
```

The verifier needs only the Python standard library. It checks the full archive hash, exact archive membership, each source file's size and hash, and the tracked input/notebook hashes. Archive files and compressed inputs are byte-exact; input text and notebook hashes normalize CRLF to LF to accommodate Git line-ending conversion. It writes nothing, does not extract the archive and does not run notebooks. A later intentional code or input revision will require a newly reviewed manifest rather than silently treating changed inputs as the recorded execution.

## Optional rerun order

The release package can be inspected without rerunning inference. To regenerate the complete audit chain, use the project scientific environment documented under `environment/` (NumPy, pandas, SciPy and statsmodels are required), open Jupyter within the repository, and execute these notebooks in order, each in a fresh kernel:

| Order | Notebook under `code/validation/` | Role |
|---|---|---|
| 01 | `01_patient_condition_sensitivity.ipynb` | Initial patient-condition diagnostic; produces baseline tables used by the later comparison audit. |
| 02 | `02_source_backed_study_design_audit.ipynb` | Reconstructs source-backed identities and verifies the 57-patient design. |
| 03 | `03_patient_level_composition_program_reanalysis.ipynb` | Aggregates regions, completes zero-count categories, verifies denominators, and tests compartment/state proportions and program scores. |
| 04 | `04_patient_level_malignant_pseudobulk_condition_reanalysis.ipynb` | Pools qualifying regional raw-count pseudobulks by patient before normalization and DE testing. |

Notebooks 02–04 also accept `GLIOMA_PROJECT_ROOT`. Notebook 01 discovers the repository from its working directory. The tracked upstream inputs are listed in `INPUT_CODE_MANIFEST.tsv`; they come from metadata standardization and primary notebooks 18, 20 and 22. The corrected sample design is generated by notebook 02. Notebook 03 additionally reads three baseline tables generated by notebook 01: `patient_condition_compartment_proportions.tsv`, `patient_condition_malignant_state_proportions.tsv`, and `patient_condition_program_scores.tsv`. Do not skip notebook 01 when recreating that comparison audit from a clean clone.

Outputs are written under `metadata/sensitivity/` into separate stage folders. These working folders remain Git-ignored. The tracked ZIP is a fixed release snapshot outside those folders. Re-execution may replace working outputs but does not replace the release snapshot. The archived `run_info.json` files record execution information; the repository environment files provide the broader software setup. A hash match is not a guarantee of numerical identity under different package versions or hardware.

## Statistical interpretation

- Composition uses all 57 patients. Program scores and malignant pseudobulk DE use 56 qualifying patients: 39 GBM, 2 LGG, 10 ndGBM and 5 rGBM.
- Compartment and state numerators and denominators are pooled across a patient's regions. Absent features are represented as zero. Program scores use malignant-cell-count-weighted averages of regional scores; pseudobulk DE sums raw counts before calculating log2(CPM + 1).
- Global composition/program tests use 20,000 label permutations, seed 1337 and BH adjustment within each reported family. Pairwise results include 5,000-bootstrap effect-size intervals.
- Only the review/ambiguous compartment meets patient-global permutation FDR < 0.05. No malignant-state proportion or program score meets its corresponding patient-global FDR threshold.
- Notebook 04 retains genes at CPM >= 1 in at least three patient libraries. Tested contrasts require at least three patients per group. LGG DE contrasts are therefore untested, not negative findings.
- The displayed strong-DE criterion is Welch-test FDR < 0.05 and an absolute difference in mean log2(CPM + 1) >= 0.5. Mann–Whitney results are retained separately. The historical notebook-01 diagnostic used different conventions and is not the authoritative final DE result.
- GBM-versus-ndGBM and GBM-versus-rGBM contrasts remain confounded by dataset origin. The exploratory unpaired within-DS3 ndGBM-versus-rGBM contrast detects no genes meeting the stated thresholds; this does not establish equivalence.
- No patient-level enrichment analysis was performed. Patient-level DE does not independently validate the historical sample-level ORA.

## Boundaries of reproduction

The patient analyses use retained upstream tables. The primary article branch preserves checked archived scVI/UMAP embeddings and the 18-cluster partition because the fresh integration/clustering rerun yielded 15 clusters at resolution 0.6. It integrates archived canonical CopyKAT predictions; a later known-normal CopyKAT rerun is separate sensitivity evidence. CellRank replays archived mapped outputs and does not refit the historical model. These limitations remain relevant even when the patient-stage results reproduce.

The primary-workflow v1.0.1 archive (`10.5281/zenodo.23015399`) predates the patient-level stage. The original patient notebook commit is `a3a8a136425ffb6dec2bdd776099eb44e84613ee`. Prepared release v1.1.0 adds the saved result package and this documentation.
